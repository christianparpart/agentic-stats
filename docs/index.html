Every machine holds everything.

Claude Code records what it does on the machine where it happened — every request, the exact token counts, the git branch, a diff of every file it touched. Then it deletes that record on a rolling window of about thirty days. There is no export and no copy anywhere else. agentic-stats runs one daemon per machine. The daemons find each other, authenticate from a shared key, and sync both ways until every machine holds the whole history. There is no server.

One binary, no server, no database

Each node collects from its own machine, keeps a full local replica, and reconciles with any peer it can reach. Nodes are equal: there is no node whose loss matters more than another's, and no node you have to keep running.

Collect

Discovers append-only transcript files, tails them from a durable cursor, and seals each record before it is written. Survives reboots, rotation, and a laptop that spends the weekend shut.

Converge

Peers exchange version vectors and ask each other for everything after a watermark. Sync runs both ways, so it does not matter which machine starts it or which was offline last week.

Read

Every node serves its own dashboard over the replica it already holds. Nothing to deploy, nothing to keep up, and no node that has to be awake for you to read your own history.

What you get

One view over every machine you work on, served from the binary itself. The same figures come back as JSON from /v1/summary and /v1/daily if you would rather query them.

An archive that replicates
Raw transcript lines kept verbatim on every node. The more machines you have, the safer the data — losing one loses nothing.
Encrypted at rest
Record bodies are sealed with a key derived from the mesh key, so a stolen laptop or a copied database file yields nothing.
Cost
API-equivalent cost from real token counts against a versioned price table, with the cache-read and cache-write split broken out — and what prompt caching actually saved you.
Time
Active coding time, busy hours, busy days, streaks, and trends by day, week, month and year.
Projects
What you actually worked on over time, joined across every machine rather than one directory at a time.
Delivery
Cost per pull request, joined exactly: the assistant records which pull request each session opened, so this is not branch-name guessing. A session that produced several splits its cost evenly between them, labelled as an allocation.
Fleet health
Which machines are still reporting, and whether the archive has gaps you should know about.
No account system
You join a mesh by holding its key. That is the whole membership model — no users, no invites, no sign-up.

One key does three jobs

agentic-stats init generates it on your first machine. Every other machine adopts the same value with join --key. Holding it is what membership means.

Admits the machine

Peers authenticate the key before they exchange anything. A node without it is not turned away politely — it is never spoken to.

Encrypts every record

Bodies are sealed before they are written, so the local database file and anything bridged through third-party storage are ciphertext.

Unlocks the dashboard

The dashboard takes the same key instead of a password. There is no separate credential to issue, rotate or forget.

Use the generated key, or any passphrase of at least 20 characters — passphrases are stretched with argon2id, because a memorable phrase carries far less entropy than its length suggests and this archive's ciphertext is exposed by design. There is no recovery if you lose it. The archive is encrypted with it.

Reaching the other machines

Three ways, in order of how little you have to configure. Nodes use whichever ones apply and do not need to agree on the choice.

Shared network

automatic

Nodes announce themselves and listen for the announcements of others. Two machines on the same Wi-Fi or the same LAN find each other with no configuration at all.

Across a tunnel

mesh.peers

Multicast does not cross a WireGuard or Tailscale link — a point-to-point tunnel is not a broadcast domain, so discovery genuinely cannot reach the far side. List those machines instead. Names are re-resolved on every dial, so hosts that move are fine.

[mesh]
peers = ["vm.example.internal:8844", "laptop.tailnet.ts.net:8844"]

Never on the same network

bridge

Point both machines at one folder and they converge through it — any synced folder, NAS or SMB share. Bundles written there are encrypted including their metadata, because the storage provider is not trusted.

[bridge]
kind = "filesystem"
path = "~/Dropbox/agentic-stats"

Getting the numbers right

Claude Code writes one line per content block, and every one of those lines repeats the complete usage object for the whole API response. Add them up and you over-count — by a different factor for each metric, so it cannot be corrected afterwards.

Measured on a real archive. The fold by requestId happens once, in internal/derive.
Metric Naive sum Folded by requestId Over-count
Output tokens 13,095,501 5,249,480 2.49×
Thinking tokens 6,278,373 2,071,020 3.03×
Cache reads 4,477,680,713 2,347,702,854 1.91×

A uniqueness constraint makes the mistake structurally impossible rather than a rule somebody has to remember. Because two nodes must return the same row for the same query, ties in the fold are resolved deterministically — otherwise replicas that agree would look like they had diverged.

Quickstart

Requires only Go. No database server, no cloud account, no certificates, no root.

  1. Build, and start a mesh on your first machine

    The key is printed once. Keep it somewhere you will still have it after the laptop is gone.

    make build
./bin/agentic-stats init          # prints the key -- there is no recovery

  2. Adopt that key everywhere else

    Every machine you want in the archive, including headless VMs.

    ./bin/agentic-stats join --key <key>

  3. Collect and serve

    The dashboard is served by the node itself. Sign in with the mesh key.

    ./bin/agentic-stats run           # dashboard on http://127.0.0.1:8899
./bin/agentic-stats once          # or a single pass and exit
./bin/agentic-stats status        # what this node holds, and its peers

  4. Start it at login

    A user service on all three platforms — launchd, systemd --user, or Task Scheduler. The daemon reads one person's home directory, so it never needs root or an administrator. On Linux it also attempts loginctl enable-linger, without which a user service stops the moment you log out — exactly wrong on a headless VM. 

    ./bin/agentic-stats install
./bin/agentic-stats service       # is it installed and running?
./bin/agentic-stats uninstall     # the archive is untouched

The dashboard binds to loopback, where http://127.0.0.1 is already a secure context in every browser — no certificate to manage and no warning. Bind it anywhere else and it switches to HTTPS with a self-signed certificate, or supply your own.

Read this before you run it

The daemon replicates full transcripts by default. That is the point — it doubles as the backup for data your machines are about to delete. Transcripts contain your prompts and your source code.

  • Every node holds everything. Adding a machine to the mesh gives that machine your whole archive, so add only machines you trust as much as the one you are reading this on.
  • Use privacy.exclude_paths to withhold projects that must never leave the machine. Excluded paths are never read, never stored and never replicated.
  • File paths are stored as plain columns so they can be queried, which means they reveal project names. If that matters for a project, exclude it rather than relying on encryption.
  • Record bodies are sealed with a key derived from the mesh key, and nothing is written to the archive unsealed — there is a test that greps the database file for exactly that.
  • Anything bridged through a synced folder is encrypted including its metadata. The storage provider is not trusted.
  • Nothing personal lives in the repository. Test fixtures are synthetic.
